# open-browser 跨平台试用

Windows x64 下载 `open-browser-win32-x64.zip` 并完整解压，运行 `open-browser.cmd`。Linux x64 解压 `open-browser-linux-x64.tar.gz` 后运行 `./open-browser`。两个包内含 Node、浏览器引擎、扩展和本机服务。Linux 需要桌面会话及匹配 Chromium 的系统动态库。Ubuntu 构建机可用 `node node_modules/playwright-core/cli.js install-deps chromium` 安装系统库。macOS 使用签名应用 `open-browser.app`。

要从桌面启动，在 Windows 解压目录的 PowerShell 中运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\create-shortcut.ps1`，桌面会出现龙形图标的 open-browser 快捷方式。Linux 在解压目录运行 `./node/bin/node install-menu-entry.mjs`，即可从应用菜单搜索 open-browser。移动解压目录后，重新执行对应命令即可更新入口。Windows 便携包及源码安装的专用引擎都内置龙形窗口图标，直接运行应用也会在任务栏显示。


首次启动后，通过 CLI 或 MCP 创建工作区并打开页面。扩展新标签页显示正在运行的 Agent 和运行历史，受管标签可通过工具栏接管或交回。扩展提供缺少凭据时的绑定面板，macOS 应用额外提供原生底部悬浮条。

## 构建与验收

在对应的 x64 平台，`npm run build` 自动选取本机目标。构建环境需要 Node.js 22 或更新版本、Python 3、curl、tar 及 npm。运行 `npm ci` 后，在仓库根目录执行对应命令。

| 目标 | 构建 | 输出 |
| --- | --- | --- |
| macOS arm64 / x64 | `npm run browser:install`，然后 `npm run build` | `dist/open-browser.app`，架构跟随构建机，需要 Developer ID Application 签名证书 |
| Linux x64 | `node desktop/build-portable.mjs linux-x64` | `dist/open-browser-linux-x64.tar.gz` 和 SHA-256 文件 |
| Windows x64 | `node desktop/build-portable.mjs win32-x64` | `dist/open-browser-win32-x64.zip` 和 SHA-256 文件 |

在 Linux 或 macOS 运行 `shasum -a 256 -c 文件名.sha256`，在 Windows PowerShell 运行 `Get-FileHash 文件名 -Algorithm SHA256` 并与随附的 SHA-256 比较。便携包可在 macOS 交叉打包。在对应平台解压包后，进入解压目录，Linux 运行 `./node/bin/node verify.mjs .`，Windows 运行 `.\node\node.exe verify.mjs .`，检查实际归档能启动服务和扩展、创建工作区并通过 CLI 读取本地测试页面，再验证临时服务退出。

无需签名证书的贡献者可运行 `npm ci`、`npm run browser:install`、`node --test clients.test.mjs control.test.mjs engine-service.test.mjs`。Linux 和 Windows CI 还运行真实扩展登录、接管测试及解压后的服务验收。签名 macOS 构建机上运行 `npm run test:all` 和 `codesign --verify --strict --deep dist/open-browser.app`；检查实际可见标签打开、接管交回、普通标签不受影响及升级后登录态。

## 发行记录

核对 `Docs/THIRD-PARTY-NOTICES.md`、分发内 `app/third-party-packages.json`、Node LICENSE、引擎的 ABOUT 与运行中的 `chrome://credits/`。保存构建所用提交、系统和架构、Node/Chromium 版本、包 SHA-256、测试输出与已知限制。CI 执行构建和验收；对外发布版本、选定项目许可证及上传 macOS 公证均由项目所有者决定。

在项目根目录运行 `python3 desktop/archive-release.py snapshot` 会生成保留执行位、固定时间戳的源码归档和校验和，包含 Git 已跟踪和未忽略的源码。归档保存在 `dist/open-browser-source-0.1.0.tar.gz`。macOS Apple Silicon 构建机可以用以下命令归档已签名应用，再比对三个发行包中的应用源文件、第三方声明与源码快照。在此期间保持工作树稳定。

```sh
ditto -c -k --keepParent --sequesterRsrc dist/open-browser.app dist/open-browser-macos-arm64.zip
(cd dist && shasum -a 256 open-browser-macos-arm64.zip > open-browser-macos-arm64.zip.sha256)
python3 desktop/archive-release.py verify
```

验证通过后，`dist/SHA256SUMS` 记录源码和三个应用归档的完整 SHA-256。
